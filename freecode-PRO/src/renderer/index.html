الأمان

قواعد الصلاحيات والـ Hooks

اسمح دائماً بأوامر محددة، واسأل عن غيرها، وامنع ما تريد. الأولوية: deny ثم ask ثم allow. الصيغة run_command(npm test:*) أو write_file|edit_file(src/**). الأوامر المركّبة (&& و; و|) تُفحص جزءاً جزءاً. الـ Hooks (PreToolUse / PostToolUse) تشغّل أمراً قبل الأداة أو بعدها؛ الخروج بالرمز 2 قبل الأداة يمنعها. يصلك مسار الملف في FREECODE_FILE.
قواعد المشروع في .freecode/rules.json بنفس الصيغة. قواعد المنع والسؤال فيها تعمل دائماً، أما السماح التلقائي والـ Hooks فتحتاج موافقتك أولاً لأنها تنفّذ أوامر على جهازك. هذه القواعد ليست sandbox: تحمي من الأخطاء الشائعة لا من شخص يتعمّد الالتفاف.

خوادم MCP

MCP يربط الوكيل بأدوات خارجية (قواعد بيانات، متصفح، GitHub…). أضف خوادمك في هذا الملف بصيغة mcpServers كما في Claude Desktop:
ملف .freecode/mcp.json داخل المشروع يعمل أيضاً لكنه يطلب موافقتك أولاً. تحتاج أدوات MCP موافقة قبل كل استدعاء ما لم تضع "autoApprove": true لذلك الخادم.
الاتجاه المعاكس (0.20.0): FreeCode نفسه صار خادم MCP — يعرض أدوات مشروعك لأي عميل MCP (Claude Desktop مثلاً) عبر npm run mcp -- --root <مشروع>، قراءةً فقط افتراضاً. التفاصيل في README.

عزل الأوامر (Sandbox)

العزل يجعل الأوامر (وتشغيل خوادم المشروع) تعمل داخل حاوية: المشروع فقط مكشوف في /work، وبقية جهازك خارجها. لو كتبتَ docker صراحةً ولم يوجد المحرّك فالوكيل يرفض التنفيذ ولا ينزل إلى جهازك خفيةً. جرّب أيضاً /sandbox في المحادثة.

خوادم اللغة (LSP)

تخدم خوادم اللغة أدوات code_definition وcode_references وcode_hover وcode_diagnostics: قفزة دقيقة إلى التعريف، ومراجع حقيقية، وتشخيصات من نفس المحرّك الذي يستخدمه محرّرك. إن لم يوجد خادم للغة فالأدوات ترجع إلى بحث نصي بسيط. ملف المشروع .freecode/lsp.json يبقى معطّلاً حتى تضغط «الثقة» لأنه يحدّد أوامر تُنفَّذ على جهازك.

جسر العقل الخارجي (موقع ذكاء اصطناعي يقود FreeCode)

يفتح موقع ذكاء اصطناعي (Arena افتراضياً) في لوحة داخل التطبيق: تلصق فيه تعليمات الجسر مرة واحدة، فيرسل أوامر FreeCode الذي ينفّذها بعد موافقتك. قواعد الصلاحيات أعلاه تنطبق عليه حرفياً: deny يمنع، وask يفرض نافذة تأكيد حتى على القراءة، وallow يعفيه من النافذة. الأوامر المدمّرة محجوبة دائماً، والمسارات محصورة في مجلد المشروع.
التعليمات تُرسل بـ /bridge send أو تُلصق يدوياً من /bridge instructions. كل استدعاء يُكتب في .freecode/bridge-log.jsonl (يُنشأ بجانبه .gitignore تلقائياً فلا يُرفع إلى git) ويُقاس في /reliability مثل أي أداة أخرى.

جسر IDE (VS Code وأي محرّر آخر)

يستمع الجسر على 127.0.0.1 فقط ويتطلب رمزاً في كل طلب، فتستطيع المحرّرات والإضافات (مثل إضافة VS Code في ide/vscode) أن ترسل طلباً وتتابع البث الحي. الرمز سرّي: لا تشاركه، وبإمكانك تدويره في أي لحظة. أعِد فتح نافذة الإعدادات لقراءة أحدث حالة.
